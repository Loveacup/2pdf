# Markdown to PDF — Detailed Reference

Detailed documentation for `scripts/md2pdf_chrome.py` internals: pagination rules, font sizing, Mermaid diagrams, Obsidian callouts, and CSS customization.

## Semantic Pagination (P1)

Chromium performs page fragmentation in the final print flow; no simulated 970px
page positions are used. All heading levels request `break-after: avoid`, and
their first sibling requests `break-before: avoid`. Callout titles, summaries and
separators stay with the next fragment. Existing explicit page-break markers remain.

Before PDF printing, the viewport matches CSS `@page` content width. The renderer
measures short code blocks, Callouts, blockquotes, lists and tables: blocks below
80% of the printable height request `break-inside: avoid`; larger blocks allow
splitting. Long paragraphs retain widow/orphan rules. Images fit the printable
width/height without cropping. This avoids a global keep-together rule for
multi-page content. Section wrappers remain semantic grouping, not page boxes.

Reproducible P1 synthetic samples are generated by `tests/p1_samples.py`.
CI pins Playwright 1.58.2 (bundled Chromium revision 1208); fonts/OS remain
environment-specific and must be recorded alongside visual evidence.

## Content-Adaptive Font Sizing

Font sizing is handled at two levels:

**Script defaults (automatic via CSS):**

| Content Type | Base Size | Notes |
|-------------|-----------|-------|
| Body text | 13px | Base size |
| Blockquotes | 12.5px | Nested → 12px |
| Callout body | 12.5px | Callout lists → 12px |
| Tables | 11.5px | No column-count shrinking; explicit density classes may use 10–10.5px |
| Nested lists | 12.5px | 2nd level → 12px |
| Code blocks | 10.5px | Fixed |

**Claude Code relay classes (inserted per section via CLI flags):**

| Class | Font Size | Use Case |
|-------|-----------|----------|
| `.text-sm` | 12px | Dense H4 subsections, detailed specs |
| `.text-xs` | 11px | Reference tables, appendix content |

### P1 tables

A4 tables remain semantic tables with all columns and cells, fixed page-width
layout and wrapping (including inline code/CJK). `thead` is a repeating header
group with an explicit keep rule; body rows taller than 80% of a page may split.
Before PDF delivery, cells below 10px, fewer than two ems of inner width, horizontal
cell overflow or a table wider than the printable area fail with table/cell
diagnostics. Choose a wider page or simplify the table; no silent compression,
screenshots or A4 mobile-card substitution is applied. Existing mobile cards
remain mobile-only.


## Code Syntax Highlighting

Fenced code blocks are syntax-highlighted via pinned **local highlight.js**, embedded as data URIs (no CDN fallback):
- **Default theme**: `atom-one-dark` (matches dark code block background)
- **Academic theme**: `atom-one-light` (matches light code block background)
- CSS overrides ensure highlight.js doesn't conflict with the dark `pre` background
- Supports all highlight.js languages automatically

## PDF Bookmarks

Chromium generates the outline natively at render time (`page.pdf({ outline: true, tagged: true })`, Playwright ≥1.42):
- Bookmark tree derives from the HTML heading structure — hierarchy and target pages are exact (no text-search page mapping)
- `tagged: true` additionally emits PDF/UA accessibility structure tags (~2% size cost)
- All generated pages are retained, including pure image/vector pages, short signatures/tails and intentional blanks. `remove_blank_pages()` returns zero without rewriting the file; text length is never evidence for deletion. Metadata uses pypdf `PdfWriter(clone_from=...)` so native outline and StructTreeRoot survive.
- The pypdf bookmark builder (`add_pdf_bookmarks`) auto-skips when a native outline exists and remains available for PDFs without one.

## Local Image Embedding

Images are frozen as base64 data URIs before rendering; Chromium checks their decoded dimensions before producing any artifact. Missing/unreadable/corrupt images fail with the source reference. The same policy covers raw HTML, CSS imports/URLs/fonts, SVG references and iframe documents, including resources nested inside data URIs.

### P0-B resource authorization (breaking change)

- **Local roots:** only the source Markdown's real parent directory is implicit. Repeat `--resource-root DIR` to grant sibling asset trees. References are URL-decoded, normalized and symlink-resolved before real-root containment checks. Spaces/Unicode paths work; source files remain read-only. Internal pinned vendor files are read separately and do not grant the document access to `scripts/`.
- **Offline default:** HTTP(S) resources fail explicitly with a migration hint. Move assets below authorized roots or repeat `--allow-origin https://host[:port]`. This is exact origin matching, not a host/path wildcard. Every resource fetch and redirect is checked; a cross-origin redirect requires separate authorization.
- **Remote mode:** authorized resources are fetched without proxy environment, cookies, browser profile or implicit authentication, recursively sanitized and frozen. The remote service can itself forward data; this policy does not constrain its internals.
- **Browser boundary:** a new isolated Playwright context blocks service workers. Request interception permits only the invocation HTML and frozen data resources; CSP denies networking and permits nonce-bearing controlled renderer scripts. Document scripts, event handlers, active embeds and base/refresh elements are removed. Exported HTML/WeChat keeps rendered DOM, not runnable document/render scripts.
- **Vendor/fallback:** missing local Mermaid/highlight.js/CSS is an error; explicit setup downloads assets, ordinary rendering never does. System Chrome runs through the same Playwright policy. The old `--fallback pandoc` path is deliberately refused because its CLI loading cannot enforce equivalent interception; migrate to `--browser chrome` / `auto`.

### P0-B invocation isolation

PDF, PNG, HTML and WeChat share `pdf_delivery.py` staging. One private directory beside the target holds the HTML, Node scripts, rendered artifact and post-processing files. Nonblocking kernel locks key the normalized real output path: the losing same-target invocation fails immediately; locks release on process exit, and leftover lock inodes hold no ownership state. Different targets remain independent.

Only a valid new artifact replaces the target atomically; PDF additionally applies requested verification. Exceptions and handled SIGINT/SIGTERM remove the private stage and stop only that invocation's Node/browser process group. Hard-kill leftovers are not reused; immediate hard-kill cleanup is not promised.

## PDF Delivery and Strict Acceptance

Both renderers use a private same-filesystem staging directory and hold target ownership before reading document resources. Renderer success requires a successful process exit and a valid artifact, not the presence of an old target. Bookmarks/metadata and requested PDF verification apply to the staged artifact; only an accepted artifact is atomically moved to the target.

- `--verify`: runs `verify_pdf.py` in a separate process, rejecting error-level findings. Warnings and skipped checks remain visible, preserving the existing error-only policy.
- `--verify-strict`: implies `--verify` and also rejects skipped **required** checks. Page parsing/content checks require `pypdf`; Mermaid input requires diagram-count metadata. Optional/not-applicable checks (such as diagram counts for a source without Mermaid) can skip.
- `--require-text TEXT`: repeatable body-text sentinels; implies `--verify`. A missing sentinel is an error. Supply the exact expected body text; comparisons normalize Unicode and whitespace, not image pixels.
- `verify_pdf.py file.pdf --src source.md --strict --require-text "Signed: Alex" --json` exposes `checks` with `status`, `required`, and `reason`, in addition to the existing findings/summary. CLI exit is nonzero for errors or skipped required checks in strict mode.
- A legitimate image-only page may report a text-extraction warning but passes strict acceptance. Text extraction does not replace viewing the actual pages.


## Custom Themes

Themes are auto-discovered from `scripts/themes/*.css`. Each CSS file has a TOML-style metadata header:

```css
/*
[theme]
name = dark
description = Charcoal background, VS Code-inspired
hljs_theme = atom-one-dark
*/
body { color: #d4d4d4; background: #1e1e1e; }
```

To add a new theme: create `scripts/themes/<name>.css` with metadata + CSS overrides, then use `--theme <name>`.

Built-in themes:

| Theme | Description | Code Theme |
|-------|-------------|------------|
| `blue` (default) | Professional blue (`#1a3c5e`), gradient tables, sans-serif | atom-one-dark |
| `dark` | Charcoal background, blue accents, VS Code-inspired | atom-one-dark |
| `academic` | Serif fonts (Palatino), minimal styling, traditional | atom-one-light |

Themes auto-discover from `scripts/themes/*.css`; the full current set (11) also includes
`warm-academic`, `editorial`, `kami`, `minimalist`, `newsletter`, `swiss`, `social-card`, `wechat-article`.
Run `--theme <unknown>` to print the live list (each CSS file carries a `[theme]` metadata header with its `hljs_theme`).

## Footnote Support

Standard Markdown footnotes via the `footnotes` extension:
- Inline references: `[^1]` renders as superscript blue link
- Definitions: `[^1]: text` renders in a compact reference section at document end
- Styled at 10px with clear visual separation

## Mermaid Diagram Support

Mermaid diagrams in fenced code blocks are automatically rendered:

- **Rendering**: pinned local Mermaid JS (explicitly provisioned by setup; missing vendor fails), `startOnLoad: false` + **per-block `mermaid.parse()` precheck + `mermaid.render()`** for timing and precise error localization
- **Fail-fast (quality gate)**: failing blocks are collected into `window.__mermaidStatus.errors`; the Python side aborts with **exit 3 and NO output file**, printing block number + error + source head. Diagram content errors never trigger engine downgrade or the pandoc lifeboat. Escape hatch: `--allow-diagram-errors`
- **Fence-first preprocessing**: code fences and inline code are placeholder-protected before `==highlight==`/wikilink/tasklist conversions — Mermaid thick arrows (`A ==> B`) are safe
- **Diagram count reconciliation**: total/rendered counts go into PDF metadata (`/JZDiagramTotal`, `/JZDiagramRendered`); `verify_pdf.py` flags mismatches and fuzzy-scans error-bomb text ("Syntax error", doubled-char variants)
- **Offline support**: `--setup` vendors `mermaid.min.js` (pinned + sha256 in `vendor.lock.json`) into `scripts/`
- **Auto-scaling**: After rendering, JS measures each SVG and proportionally scales to fit page (max 580px wide, 650px tall)
- **Natural sizing**: `useMaxWidth: false` — diagrams render at natural size, then scale down (not stretch up)
- **ViewBox preservation**: Ensures crisp rendering at any scale via SVG viewBox
- **Chrome timing**: Playwright waits for controlled Mermaid completion before printing; vendor loading is offline.


## Frontmatter display and preview

The CLI options `--properties`, `--byline`, and `--preview DIR` are defined in the
parameter reference in `SKILL.md`. The display blocks are derived from the source
YAML without changing the Markdown file. Byline rows use `author`, `cli`, and
`models`; the property card omits those fields. `--preview` writes the first page
and each page containing a named Mermaid chart as 72-dpi PNG files.

## Mermaid theme colors and chart pagination

Each available theme selects Mermaid colors globally, including flowchart lines,
pie slices, and XY-chart palettes. A diagram-level `%%{init}%%` directive retains
precedence. An adjacent bold chart-title paragraph receives `break-after: avoid`,
and its Mermaid container stays together when it fits on a page. Diagrams scaled
below 60% of their natural size produce a render-stage warning naming the block.
## Environment Self-Healing

- **Persistent venv**: `~/.venvs/pdf-skill`, shared by all CLI runtimes (they symlink the same canonical skill). Dependency-less interpreters auto re-exec into it (`JZ2PDF_REEXEC` guards loops; `--no-bootstrap` disables)
- **`--setup`**: idempotent bootstrap — venv + deps + Playwright Chromium + vendored assets + smoke render acceptance (the per-machine cross-platform guarantee)
- **Vendored assets**: mermaid + highlight.js (+ per-theme hljs CSS) pinned & sha256-locked in `vendor.lock.json`; downloaded files live next to `scripts/` and are gitignored
- **Cross-platform**: Windows venv layout (`Scripts\python.exe`), `%ProgramFiles%` Chrome discovery, `%LOCALAPPDATA%\ms-playwright` cache detection, platform temp dir instead of `/tmp`, YaHei/Consolas font fallbacks

## Obsidian Callout Support

All 26 Obsidian callout types are supported with color-coded styling:

| Category | Types | Color |
|----------|-------|-------|
| Informational | `note`, `info`, `todo` | Blue |
| Summary | `abstract`, `summary`, `tldr` | Teal |
| Positive | `tip`, `hint`, `important`, `success`, `check`, `done` | Green |
| Question | `question`, `help`, `faq` | Yellow |
| Warning | `warning`, `caution`, `attention` | Orange |
| Negative | `failure`, `fail`, `missing`, `danger`, `error`, `bug` | Red |
| Reference | `example`, `quote`, `cite` | Purple |

Foldable callouts (`> [!type]-` and `> [!type]+`) render as `<details open>` — always expanded in PDF since collapsed content would be invisible in print.

## CJK Font Rendering

| Method | CJK Support | Notes |
|--------|-------------|-------|
| Playwright bundled Chromium | Perfect | **Default** (`--browser playwright`); uses system fonts natively |
| System Chrome | Perfect | `--browser chrome`, or `auto` fallback when bundled Chromium can't launch |
| WeasyPrint | Broken on macOS | Font embedding bug — text extraction OK but visual garbled |
| pandoc + LaTeX | OK if fonts configured | Requires CJK LaTeX packages |

**WeasyPrint CJK 已知问题**: macOS 上 PingFang SC 等系统字体存于 AssetV2 哈希路径，WeasyPrint/Pango 无法正确嵌入，导致 PDF 中文显示乱码（但 pypdf 提取文本正常）。**务必使用 Chromium 系方案（Playwright bundled 默认，或 `--browser chrome` 用系统 Chrome），不要用 WeasyPrint。**
